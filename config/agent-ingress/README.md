# Agent ingress (not active)

This directory is for the traced ingress of #147. The feature is disabled. No supported command installs a file from this directory.

- The API has the optional field `spec.ingressPort`, from 1 to 65535, with no default. You cannot add, remove or change it after create.
- `make manifests` runs the generator `hack/agent-ingress-crd` after controller-gen and `hack/crd-optional`. It makes two variants of the Agent CRD. The default variant in `config/crd/bases` has the disabled gate, which refuses `spec.ingressPort`, and the annotation `koodam.dev/agent-ingress-mode=disabled`. The enabled variant in `crd/bases` of this directory does not have the gate, and it has the annotation `koodam.dev/agent-ingress-mode=enabled`. All other parts of the two variants are the same. Do not edit the two files. Run `make manifests`.
- The enabled variant has no active admission webhook yet. Thus it does not refuse a pod template port with the reserved name `http`. It is not a standalone install. Do not apply it to a cluster.
- `internal/webhook/v1alpha1` has the validator logic. It decodes an AdmissionReview v1 and the Agent strictly and returns a fixed response. `internal/agentingress` has the shared pure check of the port bounds and the reserved name `http`. No manager or install path registers the validator. `make manifests` writes the controller-gen webhook output to a temporary directory and deletes it.
- `internal/webhook/v1alpha1` also has an HTTP handler from `NewHandler`. It accepts only POST with the media type `application/json`. It limits the request body to 7 MiB, sends the body to the strict validator and writes a fixed response. It drops each panic value. Only `cmd/agent-admission` registers this handler.
- `cmd/agent-admission` is the admission binary. The image has it at `/agent-admission`, but the image entry point stays `/manager` and no install path starts it. With no argument, it is a supervisor: it starts the same binary in a private serving mode, sends the child output to `/dev/null`, forwards SIGTERM and SIGINT and writes only fixed messages. The child discards all logs, loads `/etc/koodam/agent-admission/tls.crt` and `tls.key` one time (a restart rotates them) and serves only `NewHandler` on port 9443 with TLS 1.2 or later and HTTP/1.1 only. The tests do not prove a deployed pod.
- `admission/guard.yaml` is dormant source for the admission guard. The guard name is fixed: `koodam-agent-ingress-admission`. No supported command, chart, Kustomization or workflow renders or applies it. The namespace marker and the CA marker are not valid inputs. Only the later protected installer replaces them. Never edit or apply this file by hand. The guard has `failurePolicy: Fail`. It checks `CREATE` and `UPDATE` of an Agent when the old or the new object has `spec.ingressPort`. It has no namespace selector and no object selector.
- `admission/workload.yaml` is dormant source for the admission workload. It is not an install. No supported command, chart, Kustomization or workflow renders or applies it. Never edit or apply this file by hand.
  - It has the ServiceAccount, the Service, the Deployment, the PodDisruptionBudget and the NetworkPolicy, all with the name `koodam-agent-admission`. The ServiceAccount and the pod do not mount an API token, and no Role or RoleBinding exists for them.
  - The namespace marker and the image marker are not valid inputs. Only the later protected installer replaces each marker as a whole value. The markers make the API server refuse a raw apply. An apply of many objects is not atomic, so an apply can store some objects and fail on others.
  - The Deployment runs `/agent-admission` with no argument and no environment variable. It mounts the Secret `koodam-agent-admission-tls` read-only at `/etc/koodam/agent-admission` with mode 0440 and `fsGroup` 65532. The file has no Secret.
  - The NetworkPolicy denies all ingress and all egress. Only the later installer adds one ingress rule on TCP 9443 from explicit API server CIDRs. An empty CIDR list adds no rule and keeps all ingress denied. A rule with no `from` permits all sources, so it never stands for an empty list.
  - Two replicas, the PodDisruptionBudget and the hostname spread are a configuration, not high availability. On a single-node cluster, both pods run on one node.
  - The TCP probes prove only that a process listens on 9443. They do not prove the certificate, the CA, the handler or the CNI behavior. Some CNIs apply the policy to kubelet probes or show a different source address for the API server. The maintainer must confirm the CNI behavior and the source CIDRs before activation.
  - The source tests in `cmd/agent-admission` check the exact fields of the guard and the workload. They do not prove a deployed pod, TLS readiness or an admission request.
- The manager has the flag `--agent-ingress-enabled`. The default is `false`. If the flag is `false`, an Agent that sets `spec.ingressPort` and has no `status.keyHash` waits. The controller adds no finalizer, Secret, gateway key, ServiceAccount, Role, RoleBinding or Job for it, and it keeps a finalizer or a Secret that is there. The controller writes `status.keyHash` before it makes the key, so the hash enrolls a run attempt. The hash does not show that the key or the Job exists. A finalizer, a Secret or a `Running` phase alone does not enroll a run. An Agent with a `status.keyHash` can recover with each flag value, and the revoke at the run end or at the delete always runs. Before the first Secret, key or Job, the controller also does the check of `internal/agentingress`. An Agent with no `spec.ingressPort` works with each flag value.
- The controller adds the named TCP port `http` to the main Agent container when `spec.ingressPort` is set. The Agent ingress NetworkPolicy and the ingress proxy are not installed. No chart value or install path sets `--agent-ingress-enabled`. Do not set it before the protected install is complete.
- Later #147 changes add the Secret `koodam-agent-admission-tls`, the protected installer and its input checks, the installation, the activation, the Helm value, the proxy checks and the runtime proof. Do not use this directory before these changes are merged.
- The default Kustomize, Helm and `make install`, `make deploy` and `make build-installer` paths use only the default Agent CRD. No default command can enable the ingress.
